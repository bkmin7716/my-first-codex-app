# 적용 순서

1. Supabase 백업을 확인합니다. 기존 프로젝트에는 `001-player-slots.sql` 전체를 SQL Editor에서 실행합니다. 트랜잭션이며 재실행 가능합니다. 기존 `schema.sql`은 재실행하지 마세요.
2. 새 프로젝트에만 `schema.sql`을 한 번 실행합니다. 추가 마이그레이션은 필요 없습니다.
3. SQL 적용 후 앱을 배포합니다. RPC 서명과 기존 클라이언트 호출은 유지됩니다.
4. 기존 게임은 각 참가자가 본인의 점수·지급·정산이 들어 있는 슬롯을 확인해 연결합니다. 참가 순서나 이름 일치로 과거 기록의 소유자를 추정하지 않습니다. 연결 전 기존 이름과 모든 기록을 유지합니다. 잘못 연결하지 않도록 확인 후 진행하세요.
5. 4명 모두 슬롯을 연결한 뒤 생성자가 초기 순위를 확인합니다. 초기 순위 변경은 모든 홀 잠금 해제 후 가능합니다. 기존 잠금은 유지되며 새로 1홀을 잠글 때는 4명 확정을 요구합니다.

이 SQL은 기존 게임·점수·지급·정산·이력을 삭제하거나 초기화하지 않습니다. 회원의 nullable 슬롯과 고유 인덱스를 추가하고 RPC를 교체합니다. 이름 변경은 연결된 슬롯의 이름만 수정합니다. 점수·Near·지급·정산 배열의 인덱스는 고정입니다. 이름 변경은 최종 확정 후에도 가능하며 금액은 바뀌지 않습니다.

신규 빈 게임은 생성자 슬롯 1, 이후 참가자는 비어 있는 슬롯 순서로 고정 배정됩니다. 로컬 라운드 복사는 기록 소유자를 확인하기 위해 기존 게임과 동일하게 수동 연결합니다. 미참가 슬롯은 순위 선택에 미확정으로 표시됩니다. 초기 순위 배열은 서버에 저장되고 게임 revision을 통해 전체 참가자에게 동기화됩니다.

테스트의 PostgreSQL은 PGlite, 실시간 전송은 테스트용 SSE입니다. 실제 Supabase Auth/Reatime 및 실제 기기 검증은 별도로 확인해야 합니다.
