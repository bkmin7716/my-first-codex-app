# Golf Score & Hussein

iPhone Safari용 한국어 골프 스코어·후세인 게임 정적 PWA입니다. 기존 로컬 모드는 HTML/CSS/JavaScript와 localStorage로 동작합니다. 4명 공동 플레이는 Supabase Auth·PostgreSQL·Realtime을 사용합니다.

## 실행

Node.js 22 이상에서 `npm test`로 자동 테스트를 실행합니다. 먼저 `npm ci`로 테스트 전용 의존성을 설치합니다.

로컬 실행은 `npm start` (Python 3 필요) 후 `http://localhost:8080`을 엽니다. 파일을 더블클릭하는 file:// 실행은 ES 모듈과 서비스 워커를 지원하지 않습니다. 배포 환경은 HTTPS를 사용하세요.

## 사용

1. 일반 게임(1~4명) 또는 후세인 게임(4명)을 시작합니다.
2. 골프장·날짜·선수 이름·18홀 Par를 설정합니다. 후세인은 초기 순위·정산 방식·점당 단가도 설정합니다.
3. 홀마다 1~30 정수 타수를 입력합니다. 입력 즉시 이 기기의 localStorage에 저장됩니다.
4. 후세인은 앞선 홀부터 모두 입력되어야 결과를 확정합니다. 동타는 직전 순위, 첫 홀은 초기 순위가 적용됩니다. 2등 스코어만 녹색입니다.
5. Par 3에서 Near 한 명 또는 없음을 선택합니다. 확정된 홀에 승패와 별도로 1점이 더해집니다.
6. 현황에서 전·후반/총타수, 입력홀 Par 대비, 점수, 2등 횟수, 홀 기록을 확인합니다.
7. 선불은 실제 지급 후 홀별 지급 완료를 기록합니다. 후불은 실제 수금·지급 후 선수별 완료를 기록합니다. 이 버튼들은 실제 송금 기능이 아닙니다.
8. 과거 스코어/단가/Near 수정 시 계산을 처음부터 다시 수행합니다. 실제 지급 기록과 다르면 기록을 유지하고 재정산 경고를 표시합니다. 실제 차액을 처리한 뒤 재정산 버튼으로 기록을 갱신하세요.
9. 선불 추가 수금/환급은 전체 실제 거래 금액으로 기록합니다. 후불 차액은 자동 배분하지 않습니다.
10. 라운드 종료는 18홀 완료 후 가능합니다. 종료 표시는 보관 상태이며 실제 정산 완료와 별개입니다.

목록에서 이어하기·이전 결과·삭제·복제를 사용할 수 있습니다. 복제는 스코어를 복사하고 지급/수금/환급 기록은 비웁니다. 설정의 초기화 버튼은 확인 후 타수 및 정산 기록을 비웁니다.

JSON 백업을 정기적으로 내려받으세요. 복원은 검증 및 확인 후 현재 목록 전체를 교체합니다. 데이터는 기기·브라우저·사이트 주소별로 독립적이며 Safari 데이터 삭제 시 사라집니다. 기기 간 자동 동기화는 없습니다.

## 계산 규칙

- A팀: 2등 단독. `2 × 2등 타수`와 `1등 타수 + 3등 타수`를 정수 비교합니다.
- A 승리: 전체 기본·이월 점수 독점. B 승리: 1·3·4등에게 균등 분배.
- 무승부: 기본 3점과 기존 이월을 다음 홀로 넘깁니다. Near는 이월하지 않습니다.
- 18홀 이후 이월은 미지급으로 남습니다.
- 후불은 항상 `(획득 점수 - 14) × 설정 단가`입니다. 기본 단가는 100,000 VND입니다.
- 선불금은 단가 변경과 관계없이 1인 1,400,000 VND, 전체 5,600,000 VND로 고정입니다. 상금은 설정 단가를 적용합니다.
- 선불 잔액은 실제 지급 기준이며 부족액은 전체 예정 상금 기준입니다. 실제 지급이 자금을 초과한 부족액도 별도 표시됩니다.
- 중간 결과는 임시 정산입니다. 일반 게임의 Par 대비는 입력된 홀만 반영합니다.

## 4명 공동 플레이와 배포

**설정부터 4대 휴대폰 검증까지:** [SHARED_SETUP.md](SHARED_SETUP.md)

- 홈에서 새 공동 게임 생성·참여 코드 입력을 선택합니다. 저장된 4명 라운드의 공동 게임으로 복사는 스코어와 지급·정산 기록을 모두 유지하고 원본을 변경하지 않습니다.
- 연결 확인으로 배포 설정·로그인·서버 조회·RPC 실행 여부를 구분해 확인합니다.
- 12자리 참여 코드/초대 링크로 4명이 참여하고 모두 모든 선수의 타수·Near를 입력합니다.
- Supabase 서버에 저장한 뒤 Realtime으로 전달하고, 동일한 계산 엔진으로 전체 결과를 재계산합니다.
- 변경 이력에 실제 인증 사용자 ID·표시 이름·서버 시각·변경 전후 값이 기록됩니다.
- 누구나 입력 완료 홀을 잠그고 생성자만 해제합니다. 18홀 잠금 후 생성자가 최종 정산을 확정하면 전체 데이터가 잠깁니다. 서버에서도 권한을 강제합니다.
- 단가·지급·수금·환급 기록은 생성자만 변경합니다. 동시 변경 충돌은 오래된 revision의 저장을 거부하여 덮어쓰기를 막습니다.
- 공동 기능은 Supabase 프로젝트와 공개 연결 설정, 인터넷이 필요합니다. 설정하지 않았을 때 임시 공동 게임으로 대체하지 않습니다.
- Actions가 Repository Secrets의 `SUPABASE_URL`·`SUPABASE_PUBLISHABLE_KEY`로 배포용 `shared-config.js`를 생성합니다. `sb_publishable_` 키만 허용하며 secret·JWT 키는 배포를 중단합니다. `supabase/schema.sql`을 새 Supabase 프로젝트에 한 번 설치합니다. 자세한 한국어 절차와 익명 세션 유지·운영 제약은 설정 문서를 참고하세요.
- GitHub Pages는 main 병합/푸시 후 자동 배포되며 Actions의 **골프 앱 Pages 배포**에서 수동 재실행도 가능합니다. PR에는 별도 자동 테스트 워크플로가 적용됩니다.

## iPhone 설치 및 오프라인

배포된 HTTPS 주소를 iPhone Safari에서 열고 **공유 → 홈 화면에 추가 → 추가**를 선택합니다. 처음에는 온라인으로 자산 캐시를 완료해야 합니다. 이후 홈 화면 앱에서 오프라인 사용 가능합니다. Safari 저장 데이터/캐시 삭제, 저장 공간 부족, 브라우저 정책은 저장 및 오프라인 기능에 영향을 줄 수 있습니다. Pages 빌드가 실행 번호별로 서비스 워커 캐시 버전을 자동 갱신합니다. 업데이트 후 앱을 닫고 다시 여세요.

## 파일 구성

- `engine.js`: UI와 분리된 순수 계산·검증 함수
- `storage.js`: localStorage 저장 및 JSON 백업 검증
- `app.js`, `index.html`, `style.css`: 한국어 반응형 화면과 상호작용
- `manifest.webmanifest`, `sw.js`, `icon-*.png`: 설치 및 오프라인
- `tests/engine.test.js`, `tests/ui.test.js`: 자동 검증
- `.github/workflows/pages.yml`: Secrets 설정 주입 및 자동 Pages 배포

## 검증

- `npm test`: 기존 계산·저장·화면 35개, 공동 클라이언트 4개, PostgreSQL 권한·잠금·충돌·감사·재계산 11개 시나리오를 검사합니다.
- `npm run test:browser`: 서로 격리된 모바일 Chromium 컨텍스트 5개 (PR CI는 WebKit도 실행)와 PGlite DB로 생성·참여·정원·입력·동기화 이벤트·Near·잠금·이력·오프라인·재접속 목록·로컬 원본 보존을 검사합니다. `npx playwright install chromium`이 필요합니다.
- DB 테스트는 실제 PostgreSQL 엔진인 PGlite에서 RLS·RPC를 실행합니다. 브라우저 테스트의 인증과 이벤트 전송은 테스트 전용 어댑터입니다. 제품 코드에는 이 어댑터가 포함되지 않습니다.
- 실제 Supabase 프로젝트의 Auth·Realtime 설정 및 실제 iPhone 4대 동작은 사용자의 서비스 설정 후 별도 확인이 필요합니다. 검증 절차는 SHARED_SETUP.md에 있습니다.

새 파일: `shared.js`(Supabase 연결·동기화), `shared-ui.js`(공동 플레이 화면), `shared-config.js`(공개 설정), `supabase/schema.sql`(서버 데이터·권한·변경 RPC), `tests/shared-*.test.js`(공동 기능 검증).
